# GPUIE 0.9.7 β（準備版）

Kavitaのページめくりで、準備済みの処理済み画像をスライドの最初から最後まで使うよう修正する。特に全画面・見開きで、線色フィルターの適用前の元画像がスライド中だけ混ざる経路を修正した。

## 変更

- `content/reader-core.js` のスライド画像選択で、先読み・履歴だけでなく、通常表示用へ移った処理済みBlobも参照する。
- 処理済みURLが存在する場合はそのURLを採用する。受け渡し途中なら元画像へ戻さず、既存の待機レイヤーから準備済み画像のスライドへつなぐ。
- 採用したURLは既存のスナップショット／借用管理で固定する。スライド中は再選択・再処理・再エンコードせず、完了／中断時に借用を返す。通常のキャッシュ所有権は維持する。
- Manifestの版を0.9.7へ更新。公開API、GPU演算、Komgaのページ送り、設定項目、権限、CSPは変更しない。

キャッシュ自体がない場合のKavita元画像スライドは維持する。Kavita本来のページ移動、操作、読書進捗は遅延させない。

## 検証方法

`kavita-motion-cache-browser.cjs` は実際のCore・キャッシュ・motion・WebGL／Workerと線色強制青フィルターを使用する。単ページ／見開き／見開きマンガ × 左右方向 × 通常／全画面 × Worker／速度優先の24条件が対象。

前後8/8をデコード済みにしてから、通常表示のBlob反映を片側50ms保留し、黒い元画像がレイヤーに混ざらないこと、青い画素、スライド中のURL固定、表示ページの画像処理追加がないことを確認する。OFF時の借用解放と、全画面RTL見開きWorkerでの連続送りも確認する。HTTPとWorker接続の転送部分はフィクスチャであり、インストール済み拡張や実機Kavita全版の検証ではない。

旧コードでは同じ試験が元画像URLの混入で失敗する。既存の元画像スライド、左右方向、対象外条件、章移動、離脱、URL解放のテストも回帰対象とする。

## 確認結果

- Nodeテスト38件成功。
- 旧コードは準備済みBlob以外のURLをスライドで使うため回帰試験が失敗し、修正後は成功。
- キャッシュ有りの24条件と、全画面RTL見開きWorkerの連続送り・OFF解放を確認。
- 既存の元画像スライド12条件と、自動全画面・設定OFF・手動解除の試験が成功。

これらはブラウザーフィクスチャでの確認結果。ユーザーの実機での解消確認は未完了。

## 配布

実機確認用ZIPとストア提出用ZIPを別に用意する。提出用だけManifestの`key`を除く。ストアIDは`figjcigclokemfffhialoccnodjghjoe`、手動確認版は従来の公開鍵を維持するため別IDになる。両方を有効にしないこと。

この準備版ではmainへのマージ、Tag作成、GitHub Releaseへの本体ZIP・CRX追加、ストアへのアップロードは行わない。
