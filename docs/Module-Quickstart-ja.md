# 最初のフィルターを作る

[日本語](Module-Quickstart-ja.md) | [English](Module-Quickstart-en.md)

JavaScriptとGLSLの基本が分かる方向けの入門です。GPUIE 0.9.5 β・公開モジュールAPI 1.0で、画像の明るさを変えるフィルターを読み込み、コードを修正して更新するところまで試せます。

画像の取得・表示、設定画面の生成、調整値の保存は本体が担当します。このサンプルにビルドやnpmパッケージのインストールは必要ありません。

## 1. サンプルを保存する

[Brightness-Filter-1.0.0.js](../examples/Brightness-Filter-1.0.0.js)を開き、GitHubの **Raw** からJavaScript本体を保存してください。GitHubのHTMLページを保存しないでください。Source ZIPでは `examples/` に同じファイルがあります。

GPUIE本体の導入とサイト登録が済んでいない場合は、[READMEの最初の設定](../README.ja.md#最初の設定)を参照してください。ブラウザーの拡張機能設定で、GPUIEのユーザースクリプト実行を許可します。

## 2. 読み込んで、変化を見る

1. 詳細設定の「画像処理」→「後フィルター」を開きます。
2. 「パッケージ読み込み…」で保存した `.js` を選びます。
3. 「選択編集」で「明るさサンプル」にチェックを入れ、「OK」で確定します。
4. 読書画面へ戻り、後フィルターのクイックアイコンを押して「明るさサンプル」を選びます。押すたびにOFFと候補が順番に切り替わります。
5. 「調整」を開き、明るさを **0.2** にして適用します。少し明るくなります。**-0.2** では暗く、**0** では変化なしになります。

最初は前フィルターをOFFにして、このサンプルを後フィルターだけで使うと、効果を見分けやすくなります。フィルターはBrowserレンダラーや画像の等倍表示でも動作します。

これはsRGB各成分に一定値を加える学習用の処理です。露出補正や紙地復元とは異なり、強くすると白飛び・黒つぶれが起こります。

## 3. コードのどこを見るか

| 場所 | 役割 |
| --- | --- |
| `parameters` | スライダーの範囲・初期値を宣言。本体が画面を生成・保存 |
| `translations` | 名前・説明・ラベルの英語と日本語。英語は必須 |
| `prepare()` | GPUプログラムを作成 |
| `execute()` | 保存された調整値を受け取り、画像全体を描画 |
| `dispose()` | 作成したGPUプログラムを解放 |

実際に見え方を変えるのは、GLSL内の次の行です。RGBだけを変更し、透明度は維持しています。

```glsl
outColor = vec4(clamp(color.rgb + brightness * 0.5, 0.0, 1.0), color.a);
```

## 4. 修正して、再登録する

同じ `id`・同じ `version` は重複登録できません。ファイル名だけを変えても更新にはなりません。

1. 保存したファイルのコピーを `Brightness-Filter-1.0.1.js` として作ります。
2. 上のGLSLの行から `* 0.5` を取り除きます。

   ```glsl
   outColor = vec4(clamp(color.rgb + brightness, 0.0, 1.0), color.a);
   ```

3. 宣言の次の2項目を変更します。`id: 'example.brightness'` は維持します。

   ```js
   version: '1.0.1',
   implementationRevision: 'brightness-2',
   ```

4. 同じ「後フィルター」の「パッケージ読み込み…」から修正版を読み込みます。追加・更新の画面で、更新対象に1.0.0を指定し、**「更新」** を押します。
5. **読書ページを一度再読み込み**し、サンプルを選択して明るさ **0.2** を適用します。同じ値でも、以前より明るくなれば修正が反映されています。

更新では互換性のある調整値と候補を引き継ぎます。初期値だけを変えても、保存済みの調整値は自動では変わりません。この入門ではパラメーターの名前・型・範囲を変えずに更新します。

旧版と比較したい場合は、更新の代わりに **「追加」** を選びます。旧版を残して別バージョンを登録できるので、それぞれをクイック操作の候補へ入れて比較できます。別の機能として作り始めるときは、`id` も自分の固有名に変えてください。

## うまく動かないとき

| 状況 | 確認すること |
| --- | --- |
| 同じID・バージョンが登録済み | `version` を上げたか。実装を変えたら `implementationRevision` も更新 |
| 読み込めても実行されない | ユーザースクリプト実行許可、サイト登録、本体ON、サンプルの選択 |
| 変化しない | 明るさが0でないか。変更した値を適用したか |
| 更新後も古い動作 | 読書ページの再読み込み、選択した版、保存したファイルの内容 |
| 登録・描画エラー | 画面のエラーを確認。詳細設定の「開発者・診断」で開発者モードをONにして、現在の画像の診断を確認 |

次は[API仕様書](../GPU-Module-API-Spec-ja-1.0.md)の4項（調整GUI）、5・6項（画像とGPUホスト）を参照してください。CPU解析を使う場合は7項、診断の詳細は11項にあります。[配布モジュール](../reference-packages/)も実装例として参照できます。
